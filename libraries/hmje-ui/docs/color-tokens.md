# 색토큰

앱의 공개 색은 `색토큰(라이트: 색상, 다크: 색상)` 한 쌍입니다. 노드가 두 색을
보존하고, 하위 트리의 `테마` 유산을 읽어 그릴 때 선택합니다. 모든 색상스타일은
단순 쌍에서 같은 색입니다. 풍부한 디자인 시스템은 기존 UI테마의 색값·스타일·낱말
콜백을 제공합니다. 전역 색토큰 등록이나 설치 상태는 없습니다.

화면의 `물려받은 테마`를 함수에 전달하면 계산한 `색상`을 모든 색 속성에 쓸 수
있습니다. `현재테마값()`은 앱에서 폐기 예정입니다. 캔버스가 직접 색상을 필요로 하면
`UI칠색상(칠, 디자인토큰, 테마)`를 씁니다. 일반 노드는 `UI칠새김`으로 토큰을 유지합니다.

내부 표현은 UI칠의 기존 토큰/직접 값을 재사용합니다. 공급자의 역할 번호와 겹치지
않는 64비트 최상위 표지와 다크 ARGB를 토큰 자리에, 라이트 ARGB를 직접 자리에
싣습니다. 해석은 O(1)이며 할당이나 전역 등록이 없습니다. 메모 비교는 두 색을 모두 봅니다.
그라데이션의 시작/끝, 색토큰 배열 및 색토큰 정지점은 자체 칠 메타데이터를 보존하므로 같은
라이트와 다른 다크 값을 가진 두 쌍이 색 배열 해시로 혼동되지 않습니다.

풍부한 팔레트의 공개 확장 지점은 기존 `UI테마(기본에서, 색값: 처리기,
색낱말토큰: 처리기, 토큰스타일토큰: 처리기)`입니다. 낱말/스타일 콜백이 공급자 고유
번호를 내고 색값 콜백이 브랜드·테마·뉴트럴 축으로 해석합니다. 앱의 단순 쌍과
공급자의 스타일 토큰이 같은 UI칠 경로에 함께 실립니다. 함수가 가변 상태를 캡처하면
상태를 바꿀 때 새 UI테마 값을 제공해야 합니다.

`그라데이션정지점값(위치: …, 색: …)`의 기존 두 필드 생성도 유지합니다.
칠 메타데이터는 내부 필드이며, 색토큰 정지점은 공개 `그라데이션정지점` 함수로
만듭니다. 쌍의 두 모드를 바꿀 때는 새 정지점을 만들어 교체합니다.
