# 데스크톱 파일 선택

`HmjeUI`는 `파일열기선택()`, `파일저장선택()`, `폴더열기선택()`을 제공합니다. `폴더열기설정선택(초기경로, 안내문구)`에는 UTF-8 절대 시작 경로와 안내 문구를 지정할 수 있습니다. 빈 문자열은 운영체제 기본값을 사용합니다. 폴더 선택 창에서는 디렉터리를 생성할 수 있습니다.

UI 스레드에서 호출하며 반환값은 모두 `UI파일선택결과`입니다. `파일선택가능한가()`는 대상 플랫폼에 데스크톱 선택 창 구현이 있는지 보고합니다. 접근 권한이나 호출 성공을 보장하지는 않습니다. 모바일 대상에서 데스크톱 전용 동작을 숨길 때 사용할 수 있습니다.

## 반환 상태

| `상태` | 의미 |
| ---: | --- |
| `1` | `경로`에 선택한 파일 시스템 경로 하나를 UTF-8 절대 경로로 반환합니다. |
| `0` | 사용자가 취소했습니다. 파일을 열거나 쓰거나 삭제하지 않았습니다. |
| `-1` | 네이티브 인자가 잘못되었습니다. 공개 래퍼에서는 예상하지 않는 상태입니다. |
| `-2` | 플랫폼 오류가 발생했거나 데스크톱 구현이 없습니다. |
| `-3` | 선택 경로가 API의 128 KiB 상한을 초과했습니다. 경로를 잘라 반환하지 않습니다. |
| `-4` | 반환 버퍼를 할당하지 못했습니다. |

## 파일 접근과 실행 조건

선택 창은 파일을 읽거나 생성하거나 저장하지 않습니다. `상태 == 1` 이후 선택 경로에 접근할 권한이 있는 파일 API를 호출하고 오류를 별도로 처리해야 합니다. 앱 데이터 전용 `파일` 도우미가 임의의 선택 경로에 접근 권한을 부여한다고 가정하지 마십시오. 저장 경로를 선택했다는 사실도 내용 저장의 성공을 뜻하지 않습니다.

네이티브 선택 창은 호출 종료 후 HMJE 메모리를 보관하지 않습니다. 현재 API는 동기·모달 방식이므로 백그라운드 작업이나 앱 잠금을 보유한 상태에서 호출하지 마십시오.

## 플랫폼 구현

macOS는 메인 스레드에서 AppKit의 `NSOpenPanel`·`NSSavePanel`을 사용합니다. Windows는 STA의 `IFileDialog`를 사용하며 셸 가상 항목 대신 파일 시스템 경로를 반환합니다. 폴더 모드에는 `FOS_PICKFOLDERS`를 설정합니다.

Linux는 데스크톱 포털 또는 zenity를 사용하며 폴더 안내 문구를 지정한 경우 zenity를 사용합니다. iOS·Android·semtleOS는 `-2`를 반환합니다. 이들 플랫폼의 문서 선택기·포털 수명을 데스크톱 파일 시스템 경로의 수명으로 대체하지 않습니다.

공개 래퍼는 [ui_file_dialog.hmje](../Sources/HmjeUI/ui/ui_file_dialog.hmje), 플랫폼 구현은 [Native/DesktopFiles](../Native/DesktopFiles/)에 있습니다. 앱에서 각 데스크톱 대상의 파일 접근·샌드박스 권한·취소·저장 오류를 확인하십시오.
