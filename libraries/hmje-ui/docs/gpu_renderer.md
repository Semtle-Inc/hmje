# HmjeUI GPU 렌더링

HmjeUI는 화면 구성 결과를 그리기 명령으로 기록하고 HmjeGPU를 통해 플랫폼 그래픽 백엔드에 전달합니다. 화면 레이아웃·텍스트 셰이핑·명령 기록은 CPU에서 수행하며, GPU 명령 백엔드는 최종 표면의 픽셀을 렌더링합니다.

## 구성

| 계층 | 역할 |
| --- | --- |
| HmjeUI | 화면 구성·입력·상태·레이아웃과 프레임 실행 |
| HmjeGraphics | 그리기 명령·CPU 재생·GPU 명령 변환·백엔드 탐지 |
| 플랫폼 어댑터 | 운영체제 창·표면·셰이더·텍스처 수명·표시 |

HmjeUI와 HmjeGraphics는 이 라이브러리에, 호스트 어댑터는 공개 소스의 [platforms](../../../platforms/)에 포함되어 있습니다. GPU 렌더링과 네이티브 플랫폼 뷰의 합성은 별도의 기능입니다. GPU 백엔드가 있다는 사실만으로 임의의 네이티브 뷰 합성을 지원하지는 않습니다.

## 명령 ABI와 실패 정책

`GPU_COMMAND_QUERY`는 네 워드로 ABI 버전·백엔드 종류·지원 명령 비트 집합·CPU 래스터 허용 여부를 반환합니다. Beta 1의 명령 ABI는 v2입니다. 다른 ABI 버전을 보고한 백엔드는 첫 `BEGIN` 전에 거부합니다.

Metal·GLES·D3D 호스트 백엔드는 최종 표면 전체의 CPU 래스터화를 허용하지 않습니다. 명령 실패 시 앱 루프는 `ui-display:hosted-gpu-command-failed` 진단으로 종료합니다. CPU에서 완성한 프레임버퍼를 GPU에 업로드하는 대체 경로로 계속 실행하지 않습니다.

SemtleOS와 화면을 만들지 않는 headless 검사에서는 백엔드가 CPU 래스터 허용을 보고할 수 있습니다. CPU 대체 실행은 이 정책이 허용하는 대상에 한정됩니다. 따라서 레이아웃·글꼴 처리 같은 CPU 작업과 전체 표면의 CPU 래스터화를 구분해야 합니다.

## 프레임 처리

1. 화면 구성과 레이아웃 변경을 반영합니다.
2. 배경·텍스트·이미지·클립·레이어 등의 그리기 명령을 기록합니다.
3. 백엔드의 지원 범위에 따라 명령을 인코딩하고 프레임을 제출합니다.
4. GPU 제출이 성공하면 같은 명령 목록의 CPU 재생과 프레임버퍼 blit을 생략합니다.
5. CPU 래스터를 허용하는 대상에서 대체 실행이 필요하면 무효화된 CPU 표면을 복구한 뒤 표시합니다.

화면과 지속 배경은 별도의 표면을 유지합니다. GPU 성공 프레임 뒤에는 CPU 표면의 내용이 최신이라고 가정하지 않습니다. 허용된 CPU 대체 실행의 첫 프레임에서는 현재 레이아웃에서 전체 표면을 복구하고, 이후에는 유효한 표면에 부분 갱신을 적용합니다.

## 자원 수명

호스트 이미지 명령은 호출 중 원본 픽셀을 백엔드 소유 텍스처로 복사하고, 글리프 업로드도 백엔드 캐시의 소유본을 만듭니다. 명령이 성공한 뒤 HMJE 측 이미지 참조를 정리할 수 있으며 원본 주소를 GPU 완료까지 빌리는 계약이 아닙니다.

플랫폼 어댑터는 제출한 GPU 작업에 필요한 자원을 완료 시점까지 유지합니다. 비동기 실행 실패는 표면을 무효화하여 복구 대상으로 표시합니다. 백엔드별 동기화·재시도 규칙과 앱 루프의 CPU 래스터 허용 정책은 함께 적용됩니다.

## 플랫폼별 범위

Apple 호스트는 Metal, Android는 GLES, Windows는 D3D 계열의 네이티브 어댑터를 사용합니다. SemtleOS는 VirGL 장치 ABI와 사용자 공간 인코더를 사용합니다. 명령 지원은 백엔드의 QUERY 결과와 구현에 따르며, 플랫폼 간 모든 효과의 동일한 지원을 가정하지 않습니다.

공통 명령에는 사각형·둥근 테두리·그림자·선·곡선·글리프·이미지·클립·레이어 등이 포함됩니다. 복합 효과를 사용하는 앱은 대상별 지원과 출력 결과를 확인해야 합니다. 지원하지 않는 명령의 오류는 위 실패 정책을 따릅니다.
