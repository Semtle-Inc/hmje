# 데스크톱 알림

`알림권한요청()`은 비동기 함수입니다. 허용 시 1, 거부 시 0, 실패 시 음수 오류를 반환합니다. `알림게시(제목, 본문, 식별자)`도 비동기 함수이며 알림 센터가 요청을 수락하면 1, 실패하면 음수 오류를 반환합니다. 식별자는 앱이 이전 알림을 교체할 때 사용합니다. 두 호출 모두 `기다린 결과`로 결과를 받습니다.

## 클릭과 배지

`알림클릭꺼내기()`는 `UI알림클릭결과(상태, 식별자)`를 반환하며 앱 루프에서 호출합니다. 상태 1은 클릭한 알림 식별자 하나, 0은 클릭 없음, 음수는 오류를 뜻합니다. `알림클릭기다리기()`는 폴링 없이 클릭을 기다리고 같은 구조체를 반환합니다. 동시에 대기 작업 하나를 지원합니다.

`Dock배지설정(번호)`는 메인 스레드에서 Dock 배지를 설정하며 0은 배지를 지웁니다.

## 플랫폼 요구 사항

macOS는 `UNUserNotificationCenter`와 `NSApp.dockTile`을 사용합니다. Windows는 WinRT 토스트 알림을 사용하며 프로세스가 실행되는 동안 클릭을 큐에 보관합니다. Windows의 권한 요청은 현재 운영체제 알림 설정을 읽습니다.

Windows 설치 프로그램은 토스트를 게시하기 전에 실행 파일의 시작 메뉴 바로가기를 등록해야 합니다. 바로가기의 `System.AppUserModel.ID`는 프로세스가 사용하는 값과 같아야 합니다. 기본값은 `net.semtle.HunminIDE`이며 `HMJE_APP_USER_MODEL_ID`로 지정할 수 있습니다. 이 등록이 없으면 Windows는 패키지로 설치하지 않은 앱의 알림을 거부합니다.

Windows의 Dock 배지와 모바일 대상은 미지원 상태를 반환합니다.
