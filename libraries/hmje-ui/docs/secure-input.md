# 비밀번호 입력

`텍스트입력`의 `모드는 입력모드의 비밀번호`를 사용합니다. 동일 화면에
`추적 대상 비밀번호`가 있어도 종류 이름을 명시하면 충돌하지 않습니다.
함수 생성자에는 `텍스트입력비밀번호지정(텍스트입력(...))`을 씁니다.

편집 상태는 원문 문자열과 UTF-8 바이트 커서/선택 위치를 유지합니다. 정적·포커스·
호버·비활성 렌더링은 그래핀마다 `•` 하나를 표시합니다. 셰이핑, 커서, 선택,
클릭, 가로/세로 스크롤, 여러줄 수직 이동은 같은 표시 좌표를 사용합니다.
결합 문자·이모지 ZWJ·국기는 하나의 그래핀입니다. 줄바꿈도 가리며 여러줄은
가려진 문자의 소프트랩을 사용합니다. 원문을 표시하는 예외나 마지막 글자 잠깐
표시는 없습니다. 마스킹 버퍼 할당 실패 시 빈 표시로 끝나며 원문을 대신 그리지 않습니다.

접근성은 이름/역할/편집 동작을 유지하되 민감 상태32를 자동 설정하고 값은 빈
문자열로 게시합니다. 원문을 포함하는 placeholder/접근성 이름을 앱에서 지정하지
않아야 합니다. iOS 표준 트리에는 secure text field로 노출됩니다.

iOS는 secureTextEntry, Password content type, 자동 대문자화/수정/맞춤법/스마트
구두점 해제를 사용합니다. 네이티브 프록시의 복사·잘라내기·공유 동작은 차단하고
붙여넣기는 입력으로 허용합니다. Android는 PASSWORD/NO_SUGGESTIONS,
NO_PERSONALIZED_LEARNING을 지정하며 copy/cut/share context action을 차단합니다.
일반 입력으로 전환하면 언어 서비스와 여러줄 설정을 복원합니다. 공통 편집기는 원문을 클립보드로 내보내지 않습니다.

111번 TEXT_INPUT_CONTROL2가 보안 입력 경로를 확인합니다. macOS는 HmjeUI의
마스킹·편집기와 숨은 NSTextInputClient 입력 프록시를 사용하며 별도의
NSSecureTextField를 만들지 않습니다. macOS 접근성 트리는 secure text field
subrole과 빈 값을 게시하고, 복사·잘라내기 명령은 네이티브 프록시와 공통
편집기에서 모두 차단합니다. 지원되지 않는 플랫폼에서는 일반 키보드를 열지
않고 진단과 종료 코드9로 종료합니다. 기존 일반 입력104, 시스템 테마110은
그대로 유지합니다. 현재 구현 범위는 iOS/Android/macOS 앱입니다.


마스킹과 편집 구현은 [텍스트 입력](../Sources/HmjeUI/ui/ui_text_input.hmje), 플랫폼 제어 요청은 [입력 제어](../Sources/HmjeUI/ui/ui_text_input_control.hmje)를 참고합니다.
