# 변형 제스처

`변형제스처상태`는 HmjeUI의 공통 `포인터표본` 두 개를 확대, 회전, 중심 이동으로
합성합니다. 플랫폼 객체나 플랫폼 gesture recognizer를 노출하지 않으므로 iOS,
Android, Windows와 semtleOS가 같은 결과 계약을 사용합니다.

## 값 계약

- `배율`: 제스처 시작 거리 대비 누적 배율이며 시작값은 `1.0`입니다.
- `회전`: 제스처 시작 선분 대비 누적 `각도`이며 `-π...π`로 정규화됩니다.
- `중심X/Y`: 제스처 대상 화면의 지역 논리 좌표입니다.
- `중심이동X/Y`: 시작 중심 대비 누적 이동입니다.
- 두 번째 터치가 들어오면 `시작`, 이동마다 `변경`, 포인터가 빠지면 `종료` 또는
  `취소`를 한 번 냅니다.
- 마우스, 펜, 예측 표본과 세 번째 이후 터치는 인식에 섞지 않습니다.
- `변형제스처가소비중인가`가 참이면 같은 영역의 한 손가락 끌기·스크롤 후보를
  중단해야 합니다. 두 손가락 중 하나가 빠지는 종료·취소 뒤에는 거짓이 됩니다.

## 화면 DSL에서 사용하기

일반 화면 노드에 `변형 제스처는 <이름>을 받아`를 붙입니다. 전달되는 값은 확대,
회전과 두 손가락 중심 이동이 같은 기준 시점에서 계산된 `변형제스처값`입니다.

```hmje
화면 지도화면의
    추적 대상 기준배율은 1.0이고, 실수이다.
    추적 대상 표시배율은 1.0이고, 실수이다.
    추적 대상 기준회전은 영각도()이고, 각도이다.
    추적 대상 표시회전은 영각도()이고, 각도이다.

    그리는 내용은
        캔버스의
            그리기는 그래픽과 영역을 받아
                그래픽은 지도를그린다(그래픽, 영역, 표시배율, 표시회전)이다.
            변형 제스처는 변화를 받아
                만약 변화.단계가 제스처단계의 시작이면
                    기준배율은 표시배율이다.
                    기준회전은 표시회전이다.
                표시배율은 기준배율 * 변화.배율이다.
                표시회전은 각도더하기(기준회전, 변화.회전)이다.
```

같은 노드에는 `변형 제스처는`과 저수준 `포인터 입력은`을 동시에 둘 수 없습니다.
한 손가락 `끌기는`도 함께 제공한다면 콜백의 `시작`/`종료`/`취소`로 추적 대상
`변형중`을 갱신하고 `끌기는 (변형중이 거짓인지)이고,`처럼 활성 조건을 연결합니다.

`변형제스처값.회전`은 의미 타입 `각도`입니다. 그래픽 행렬이나 삼각함수에 넘기는 마지막
경계에서는 `각도의라디안`, 사용자에게 숫자로 보일 때는 `각도의도`를 사용합니다.

직접 포인터 표본을 처리하는 라이브러리는 저수준 순수 함수
`변형제스처처리(이전상태, 표본)`를 사용할 수도 있습니다. 반환된 `상태`를 저장하고
`발생`일 때만 `값`을 소비합니다. 이 API는 화면 DSL과 독립적이라 테스트나 사용자 정의
입력 라우터에서도 같은 recognizer를 재사용할 수 있습니다.
