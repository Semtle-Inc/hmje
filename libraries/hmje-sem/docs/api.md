# HmjeSem 공개 API 계약

## 층 구조

```
모델 추론·학습 프로그램
 ├─ 저수준 커널  kernels.hmje   — 무검사, 무할당(정상 상태), hot loop 전용
 ├─ 서술자 층    tensor.hmje    — 셈텐서/셈저장소 + 검사하는 eager 진입점
 └─ 그래프 층    graph.hmje     — 기록(검사·할당) / 재생(무검사·무할당)
     collections.hmje           — 미러 순환버퍼 (K/V cache, 스트리밍 링)
```

세 층 모두 같은 커널 구현으로 내려갑니다. 서술자·그래프 층은 편의와 안전이고,
성능 계약은 커널 층과 동일합니다.

## 셈텐서 서술자

`셈텐서`는 {성공, 자료형, 장치, 차원개수, 차원0..3, 보폭0..3, 데이터(버퍼뷰)}의
비소유 서술자입니다. 최대 4차원, 차원0이 가장 바깥 축이고 2차원이면 차원0=행,
차원1=열입니다(1차원은 차원0=1, 차원1=개수). 보폭은 원소 단위이고 실수 자료형에만
의미가 있습니다 — 양자 자료형은 블록 packed 2차원 고정입니다.

- 자료형 번호는 GGML type id: 실수32=0, 실수16=1, Q4_0=2, Q8_0=8, Q6_K=14,
  자연수32=26. GGUF에서 읽은 값을 변환 없이 씁니다.
- `셈텐서2차원`/`셈텐서1차원`이 만들 때 검사하는 것: 0 차원 거부, 자료형별 행
  바이트(양자 블록 배수 제약 포함), `행개수 × 행바이트`의 u64 overflow, 뷰 길이.
- 연산 진입점이 부를 때 검사하는 것: 모양 일치, dtype 규칙, aliasing.
  - 행렬곱·투영·어텐션·임베딩: 출력은 모든 입력과 겹치면 안 됩니다.
  - 요소 연산·정규화·소프트맥스: 출력이 입력과 **정확히 같은 구간**이면 허용
    (제자리), 부분 겹침은 거부. `셈부분겹침인가`가 이 판정입니다.
- 검사 실패는 출력에 아무것도 쓰지 않고 거짓을 반환합니다.

## 뷰 연산

`셈텐서`는 최대 4차원 + 원소 보폭입니다. `셈전치`(2차원 f32, 무복사 비연속 뷰),
`셈행조각`(연속 유지, 양자 자료형 포함), `셈열조각`(f32, 비연속), `셈모양바꾸기2차원`
(연속 한정), `셈연속화`(비연속 뷰를 packed로 물질화, 복사량 진단 계상). 커널은
연속 배치만 받으므로 연산 검사가 `셈연속인가`를 강제하고, 비연속 뷰는 연속화 뒤
씁니다. 요소 연산은 3·4차원 연속 텐서를 받고, 행 의미론 연산(소프트맥스·정규화·
행렬곱·어텐션)은 2차원 이하만 받습니다.

## 연산 진입점 (eager)

| 함수 | 의미 |
| --- | --- |
| `셈행렬곱` | A[M,K] × B[K,N], 둘 다 f32 |
| `셈투영` | X[M,K] f32 × W[N,K] (F16/Q4_0/Q8_0/Q6_K) → Y[M,N], dtype으로 커널 선택 |
| `셈소프트맥스` | 행별 정규화 |
| `셈RMS정규화` / `더하기` / `무배율` | rms norm (+잔차 융합/배율 없음) |
| `셈SiLU` `셈GELU탄젠트` `셈GELU탄젠트곱하기` `셈탄젠트소프트캡` | 활성화 |
| `셈요소더하기` `셈요소곱하기` | 요소 연산 |
| `셈임베딩찾기` | token id(자연수32) → Q6_K 행 gather |
| `셈어텐션` | causal/sliding MQA·GQA, 창크기 0=full causal |
| `셈RoPE` / `셈부분RoPE` | 인접쌍 / half-split 부분 회전 (제자리) |
| `셈양방향어텐션` | 인코더 어텐션, 창크기 0=전체·양수=중심 반경 창 |
| `셈층정규화` | LayerNorm (배율+이동) |
| `셈시그모이드` `셈소프트플러스` `셈요소로그` | 활성화·로그 (수치 안정형) |
| `셈합성곱1차원` | conv1d, 편향 선택·보폭·zero padding, 워커 풀 병렬 |
| `셈창곱프레임` `셈복소전력` | 오디오 프레이밍+창, 전력 스펙트럼 (DFT는 행렬곱으로 조립) |
| `셈행별합/평균/최댓값/최대위치` | 행별 reduce (argmax는 자연수32 출력) |
| `셈행모으기` `셈이어붙이기행` | f32 행 gather(색인 전수 검사) / 행 방향 concat |
| `셈변환실수16/32` | f32 ↔ f16 요소 변환 |
| `셈역양자화` | Q4_0/Q8_0/Q6_K → f32 (cold 연산) |
| `셈아핀` | y = x·배율 + 상수 (스칼라 매개, 제자리 허용) |
| `셈행쓰기` | 저장소[행번호]에 행 하나 쓰기 (미러 없음) |
| `셈가중합` | out = a·배율a + b·배율b (두 텐서 가중합) |

## 셈그래프

- 마디는 256바이트 고정 레코드(u64 슬롯 32개): 연산코드, 피연산자 4개(주소/길이/
  행/열), 자연수·실수 매개변수. 레코드 형식은 [그래프 구현](../Sources/HmjeSem/graph.hmje)의 머리 주석에 정의되어 있습니다.
- `셈그래프열기(최대마디수)`가 기록 단계의 유일한 할당입니다. `셈그래프*기록`은
  eager와 같은 검사를 통과해야 마디를 남기고, 실패 시 마디를 남기지 않습니다.
- `셈그래프실행`은 검사·할당 없이 마디를 순회합니다. 마디는 버퍼 **주소**를
  참조하므로, 같은 버퍼에 새 값을 채우고 재실행하면 새 결과가 나옵니다. 버퍼
  수명·재배치는 호출자 책임입니다.
- `셈그래프투영재사용기록`의 재사용 플래그는 eager `Q4_0행렬곱재사용`과 같은
  계약(직전 마디와 같은 입력, Q4_0 한정)입니다.
- **심볼릭 차원**: 대표(최대) 모양으로 기록해 검사를 통과시킨 뒤,
  `셈그래프슬롯심볼지정(그래프, 마디, 슬롯, 심볼)`으로 특정 차원·위치 슬롯을
  심볼 참조로 바꾸고 `셈그래프심볼바인딩`으로 재생 직전마다 값을 넣습니다(심볼
  16개). 키 개수·질의 위치만 변하는 KV decode 반복이 대상이며, 대표 모양보다
  큰 값 바인딩은 호출자 계약으로 금지합니다(버퍼·검사가 대표 모양 기준).
  **장치 드라이버는 반드시 `셈그래프차원읽기`로 슬롯을 읽어야 합니다** — 원시 슬롯을
  그대로 읽으면 심볼 태그를 값으로 오해합니다(주소 슬롯 1·5·9·13만 원시로 읽습니다).
  고정 모양 반복(ASR 인코더 블록, prefill 청크)은 심볼 없이 그대로 기록합니다.

## 셈계획 (메모리 플래너)

중간 버퍼의 수명 구간 [시작마디, 끝마디]를 등록하면 겹치지 않는 수명끼리 자리를
재사용하는 arena 오프셋을 결정적으로 배치합니다. `셈계획열기 → 셈계획구간추가 × n → 셈계획배치
(정렬) → 셈계획구간오프셋`으로 뷰를 조립해 `셈저장소` 위에 얹고, 그 뷰로 그래프를
기록합니다. 배치는 TFLite arena식 O(n²) 최저 오프셋 탐색입니다.

## 장치 그래프 재생

마디는 장치 표기(slot 27)를 함께 기록합니다. 드라이버가 둘입니다.

- `셈그래프실행` — CPU 전용. 장치 마디를 만나면 **거부합니다**. 통합 메모리라
  실행 자체는 되지만 그건 관측되지 않는 폴백입니다.
- `셈Metal그래프실행` — 연속된 Metal 마디를 한 command buffer로 인코딩하고,
  CPU 마디 앞에서 제출·대기해 순서를 지킵니다. Metal 커널이 없는 연산은 CPU로
  내려가되 `셈진단Metal폴백수`에 남습니다. 순수 Metal 그래프는 재생 한 번에
  `셈진단Metal배치횟수() == 1`입니다.

Metal 지원 여부는 연산별로 다릅니다. 투영·임베딩·정규화·요소 연산·RoPE·어텐션·순환 버퍼 쓰기 등의 장치 경로는 [Metal 구현](../Sources/HmjeSem/metal.hmje)에 정의되어 있습니다. CPU 대체 실행은 진단 계수로 확인합니다.

KV 캐시 쓰기도 그래프 마디로 기록할 수 있습니다. 캐시 슬롯의 순번은 심볼로 바인딩하여 토큰마다 변경합니다. 그래프 외부의 CPU 작업은 배치 경계가 될 수 있으므로 인코딩 시간·대기 시간·제출 횟수를 함께 측정합니다.

어텐션 커널은 online softmax로 키를 흘려보내므로 점수 scratch가 필요 없습니다 —
CPU 경로가 `키개수 × 4`바이트 임시 뷰를 요구하는 것과 다른 점입니다. lane이
head_dim을 나눠 가지므로 head_dim ≤ 512까지 지원하고, 넘으면 명시적 실패입니다.

묶음 투영(2·3)은 Metal에 별도 커널이 없습니다. 그래프에 투영 마디 2~3개로 기록되고
같은 배치에 인코딩되므로, CPU 묶음 커널이 주던 활성·barrier 공유 이득을 배치
제출이 이미 제공합니다.

## 진단 (조용한 폴백 금지)

항상 켜져 있고 hot loop 밖에서만 증가합니다. `셈진단초기화`로 0으로 만듭니다.

| getter | 뜻 |
| --- | --- |
| `셈진단할당수` / `셈진단할당바이트수` | 라이브러리 내부 heap 할당 횟수/바이트 |
| `셈진단스크래치확장횟수` | grow-only scratch(Q8 활성·어텐션 점수·RoPE 삼각) 재할당 |
| `셈진단준비실패횟수` | scratch/저장소 할당 실패 (OOM) |
| `셈진단복사바이트수` | 커널 층의 버퍼 복사 (현재 Q4_0 8행 재배치만) |
| `셈진단어텐션병렬횟수` / `셈진단어텐션순차횟수` | 어텐션 워커풀/순차 경로 선택 |
| `셈진단Q4캐시재사용횟수` | Q4_0 활성 양자화 생략 (재사용 경로) |
| `셈진단RoPE폴백횟수` | 삼각 scratch 실패로 헤드별 재계산 폴백 |
| `셈진단Metal실행횟수` / `폴백횟수` / `실패횟수` | GPU 디스패치 / CPU로 내려간 장치 마디 / 어댑터 실패 |
| `셈진단Metal배치횟수` | 제출한 command buffer 수 (그래프가 얼마나 끊겼는지) |
| `셈진단Metal인코딩마이크로초` / `대기마이크로초` | CPU 인코딩 / GPU 제출+완료 대기. 둘의 비가 이 경로가 CPU에 묶였는지 GPU에 묶였는지를 가릅니다 |

scratch 확보가 실패한 행렬곱은 출력을 0으로 채우고 반환합니다(값 오염 없는 결정적
실패). 발생하면 `셈진단준비실패횟수`가 증가하므로 벤치·테스트에서 잡습니다.

`텐서프로파일*`은 호출 수와 마이크로초 누계를 제공하며 기본 비활성입니다. 성능을 측정할 때에는 프로파일 활성화 여부를 함께 기록합니다.

## 워커 풀

행렬곱·어텐션 커널은 상주 pthread 풀과 세대 배리어로 작업을 분배합니다. 이 저수준 경로는 `위험 작업`으로 구현되어 있으며 공유 데이터와 호출 순서의 동기화가 필요합니다. `텐서병렬작업자수설정`은 첫 행렬곱 전에 호출하고 사용 종료 시 `텐서병렬종료`를 호출합니다.
