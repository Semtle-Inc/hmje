# 샘플링과 토큰 스트리밍

[sampler.hmje](../Sources/HmjeLLM/sampler.hmje)는 모델에 독립적인 범주형 샘플러입니다. `로그잇샘플러열기`로 어휘
크기의 토큰 ID·f32 후보 작업공간을 한 번 할당하고 생성이 끝날 때 닫습니다. 반복 계산에서는
동적배열이나 클로저를 새로 만들지 않습니다.

`로그잇샘플`의 규칙은 다음과 같습니다.

- 온도 `<= 0`: 난수 생성기를 소비하지 않는 첫 번째 최댓값의 인덱스
- top-k `0`: 전체 어휘, 그 외에는 상위 `min(k, vocab)` 후보
- top-p `(0, 1)` 안: 정렬된 후보의 누적 확률이 p 이상인 최소 누적 확률 기준 후보군
- top-p가 범위 밖: `1.0`
- 난수 시드 `0`: 고정 비영 상태로 정규화한 xorshift64 상태

후보 선택은 전체 정렬 대신 최대 힙 생성 `O(vocab)`과 k회 추출 `O(k log vocab)`을 씁니다.
Gemma 소프트캡은 단조증가이므로 top-k 순서를 바꾸지 않습니다. 따라서 전체 어휘이 아니라 추출된
후보의 확률 계산에만 소프트캡을 적용합니다. top-k 40에서는 262,144회 쌍곡탄젠트를 40회로 줄이면서
소프트맥스·누적 확률 기준 후보군 확률은 동일하게 유지합니다.

`Gemma4샘플스트리밍생성`은 토큰이 정해지는 즉시 `자연수32를 받아 반환하지 않음` 처리기를
호출합니다. 처리기는 생성 호출 전에 한 번 만들어 재사용합니다. [GemmaStream 예제](../Sources/GemmaStream/main.hmje)는 토크나이저를 캡처한 처리기로 토큰을 디코드하여 표준출력에 씁니다. 모델 준비와 빌드는 [추론 문서](inference.md)를 참고합니다.

종료 토큰도 처리기에 한 번 전달되며 반환값은 전달된 전체 토큰 수입니다.
