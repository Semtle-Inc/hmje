# 컨테이너 변경과 메모리 부족

`추가`, `설정`, 배열 원소 쓰기, 공유 배열 분리, `문자열붙이기`와
`문자열붙인값`은 필요한 메모리를 확보하지 못하면 LLVM `trap`으로 종료합니다.
원본을 성공 결과처럼 반환하거나 공유 원본에 대신 쓰지 않습니다. 필요한 길이·용량을
표현할 수 없는 경우에도 같은 규칙을 적용합니다. 원시 `메모리할당`과
`…새데이터`는 여전히 0 주소를 반환하므로 명시적인 복구 처리는 가능합니다.
문자열에 빈 조각을 붙이는 것처럼 할당이 필요 없는 변경은 계속 성공합니다.

내장 원소 배열과 준비 단계에서 생성하는 구조체·문자열 배열에 같은 규칙이 적용됩니다.
외부 구현 선언을 통해 `llvm.trap`을 호출합니다.

명시적인 실패 결과를 반환하는 JSON `추가시도`는 낮은 수준의 할당 결과를
검사하고 실패 센티널을 반환합니다. 파싱 실패와 빈 직렬화 결과라는 기존 JSON
계약은 유지합니다. 원본을 성공한 변경처럼 반환하는 일반 변경과는 다른 API 계약입니다.
