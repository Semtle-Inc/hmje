# HMIR v0.1

HMIR은 훈민정음 프론트엔드와 LLVM 백엔드 사이의 중간 표현입니다. 표면 문법이 자연어에 가깝다면, HMIR은 기계적으로 읽기 쉬운 한글 명령어 집합입니다.

자립 컴파일러는 타입 검사 이후 HMIR을 만듭니다(`compiler/Sources/HMIR생성`). `--target hmir`는 이를
텍스트 형식으로 출력하고, `.hmir` 파일을 입력으로 주면 프론트엔드를 건너뛰고 백엔드
(`hmir을llvm으로`)만 실행합니다.

```sh
bin/hmjec --target hmir compiler/examples/abi.hmje -o build/abi.hmir
bin/hmjec --target llvm-ir build/abi.hmir -o build/abi.ll
```

## 목표

- 타입 검사 이후의 명확한 프로그램 구조를 표현합니다.
- 자연어 문법의 모호성을 제거합니다.
- 훈민정음 컴파일러의 중간 결과를 텍스트로 확인할 수 있습니다.
- LLVM 변환 전에 타입·소유권 검증에 필요한 정보를 유지합니다.

## 기본 구조

HMIR 파일은 모듈로 시작하고 끝납니다.

```hmir
모듈 훈민정음
  ...
모듈끝
```

들여쓰기는 구조를 보여주기 위한 출력 형식입니다. 의미상 블록 경계는 `함수끝`, `위험구역끝`, 라벨과 분기 명령으로 결정됩니다.

## 이름

임시값은 SSA 스타일 번호를 사용합니다.

```hmir
%1: 정수 = 상수값 42
%2: 정수 = 읽기 값
```

라벨은 점으로 시작합니다.

```hmir
.반복조건_1:
.반복본문_2:
.반복끝_3:
```

함수 심볼은 타입 시그니처를 포함합니다.

```hmir
@더하기[정수, 정수]
@작은배열[]
@외부:hmje_arch_syscall3[자연수, 자연수, 자연수, 자연수]
```

## 타입 표기

HMIR은 사용자에게 보이는 타입 이름을 기본으로 출력합니다.

```hmir
정수
자연수8
문자열
주소
자연수8 3개의 고정배열
사람형
```

구조체 타입은 모듈 앞쪽에 선언됩니다.

```hmir
타입 사람형 = 구조체 { 이름: 문자열, 나이: 정수 }
```

## 리터럴과 값 생성

상수 리터럴:

```hmir
%1: 정수 = 상수값 42
%2: 문자열 = 상수값 '훈민정음'
%3: 참거짓 = 상수값 참
```

선택값의 실제 `없음`은 payload 초기화 식을 만들지 않고 의미를 보존합니다.
등록된 선택 타입에 한해서 다음 상수를 사용할 수 있으며, 지역/전역 모두
해당 LLVM aggregate의 `zeroinitializer`로 낮춥니다.

```hmir
%4: 사람형? = 상수값 없음
```

등록되지 않은 일반 구조체나 스칼라에 `상수값 없음`을 쓰면 오류입니다.
`구조체값 ...(있음: false, 값: 호출결과)`를 이 상수로 추정하지 않으므로,
명시적으로 작성한 payload의 평가와 전역 상수 제약은 그대로 유지됩니다.

파일 데이터:

```hmir
%1: 자연수8 2097152개의 고정배열 = 파일데이터 'runtimes/limine/framebuffer_text/fonts/unifont-bmp-16.0.04.bin'
```

구조체 값:

```hmir
%3: 사람형 = 구조체값 사람형(이름: %1, 나이: %2)
```

배열 값:

```hmir
%4: 자연수8 3개의 고정배열 = 배열값 [%1, %2, %3]
```

## 지역 값과 전역 값

지역 상수와 변수:

```hmir
상수 이름: 문자열 = %1
변수 횟수: 정수 = %2
```

전역 상수와 변수:

```hmir
전역상수 기본폰트: 자연수8의 고정배열 = %1 [섹션 '.rodata', 정렬 16]
전역변수 hmje_cursor_x: 정수 = %2
```

외부 전역:

```hmir
외부전역 장치상태: 자연수32
```

## 읽기와 쓰기

값 읽기:

```hmir
%1: 정수 = 읽기 횟수
```

값 쓰기:

```hmir
쓰기 횟수 = %2
쓰기 민수.나이 = %3
쓰기 바이트목록[%4] = %5
쓰기 바이트목록[순번 %4] = %5
```

주소 얻기:

```hmir
%1: 주소 = 주소값 값
```

필드 읽기:

```hmir
%2: 문자열 = 필드읽기 %1.이름
```

인덱스 읽기:

```hmir
%3: 자연수8 = 인덱스읽기 %1[%2], 영기반
%4: 자연수8 = 인덱스읽기 %1[%2], 순번
```

`영기반`은 `[]` 접근이고 0부터 시작합니다. `순번`은 `번째 요소` 접근이고 1부터 시작합니다.

## 연산

산술:

```hmir
%3: 정수 = 더하기 %1, %2
%3: 정수 = 빼기 %1, %2
%3: 정수 = 곱하기 %1, %2
%3: 정수 = 나누기 %1, %2
```

비트:

```hmir
%3: 자연수32 = 비트곱 %1, %2
%3: 자연수32 = 비트합 %1, %2
%3: 자연수32 = 비트배타합 %1, %2
%3: 자연수32 = 왼쪽이동 %1, %2
%3: 자연수32 = 오른쪽이동 %1, %2
%3: 자연수8 = 비트반전 %1
```

형변환:

```hmir
%2: 자연수32 = 변환 %1, 자연수32
```

비교와 논리:

```hmir
%3: 참거짓 = 비교 >= %1, %2
%4: 참거짓 = 부정 %3
%5: 참거짓 = 논리곱 %3, %4
%6: 참거짓 = 논리합 %3, %4
```

## 함수

함수 정의:

```hmir
함수 더하기(a: 정수, b: 정수) -> 정수
  ...
함수끝
```

외부 함수:

```hmir
외부함수 hmje_arch_syscall3(번호: 자연수, 인자1: 자연수, 인자2: 자연수, 인자3: 자연수) -> 정수
```

함수 호출:

```hmir
%3: 정수 = 호출 @더하기[정수, 정수](%1, %2)
%5: 정수 = 호출 @외부:hmje_arch_syscall3[자연수, 자연수, 자연수, 자연수](%1, %2, %3, %4)
```

반환:

```hmir
반환 %3: 정수
```

값을 버리는 호출 결과:

```hmir
버림 %3: 정수
```

일반 위치 인자 호출을 문장으로 써서 반환값을 버리는 것은 오류입니다. 소스에서 `함수를 (이름: 값, ...)로 실행한다` 또는 `함수를 실행한다` 문장을 사용하면 반환값 discard 의도가 명시되며, HMIR에는 `버림`으로 남습니다. 버린 값이 owner 타입이면 LLVM lowering에서 즉시 release를 삽입합니다.

도달 불가능:

```hmir
도달불가
```

`종료`처럼 돌아오지 않는 호출 뒤에는 `도달불가`가 붙습니다. LLVM lowering은 이를 `unreachable`로 낮춥니다.

돌아오지 않는 호출도 스코프 cleanup을 건너뛰지 않습니다. 소스에서 `종료를 (코드: ...)로 실행한다`가 owner, borrow, pin, 선점금지 작업 안에 있으면 HMIR은 호출 전에 필요한 `빌림끝`, `주소고정끝`, owner release 호출, `커널선점허용` 호출을 먼저 배치하고, 그 뒤에 `도달불가`를 둡니다.

## 출력

HMIR에는 별도 출력 명령을 두지 않습니다. 훈민정음의 `값을 출력한다` 문장은 프론트엔드에서 `출력(값)` 함수 호출로 정규화됩니다. 기본 타입은 표준 라이브러리의 `출력`/`출력조각` 오버로드로 처리하고, 고정 배열과 구조체는 프론트엔드가 타입 정보를 바탕으로 `출력조각` 호출 묶음으로 자동 확장합니다.

## 제어 흐름

무조건 이동:

```hmir
이동 .반복조건_1
```

조건 분기:

```hmir
분기 %1, .조건참_1, .조건거짓_2
```

라벨:

```hmir
.조건참_1:
  ...
.조건끝_3:
```

while 형태 반복은 라벨과 분기로 표현합니다.

```hmir
이동 .반복조건_1
.반복조건_1:
%1: 참거짓 = 비교 < %횟수, %제한
분기 %1, .반복본문_2, .반복끝_3
.반복본문_2:
  ...
  이동 .반복조건_1
.반복끝_3:
```

`반복을 종료한다`는 반복 끝 라벨로 이동합니다. `다음 반복으로 넘어간다`는 반복 조건 라벨로 이동합니다.

## 위험 작업

위험 작업은 HMIR에도 남깁니다.

```hmir
위험구역
  ...
위험구역끝
```

타입 검사 이후에는 위험 기능이 안전 영역에 남아 있지 않아야 합니다. HMIR의 위험 작업은 감사와 백엔드 정책 확인용 표시입니다.

## 선점금지 작업

소스의 `선점금지 작업`은 별도 HMIR marker를 만들지 않고 커널 함수 호출로 낮춥니다.

```hmir
호출 @커널선점금지[]()
...
호출 @커널선점허용[]()
```

`반환`, `이동`, `도달불가`로 이어지는 noreturn 호출로 작업을 빠져나가는 경로에도 `커널선점허용` 호출을 먼저 삽입합니다. 이 기능은 위험 작업과 독립적이며, 원시 메모리 접근 권한을 부여하지 않습니다.

## 스코프 이탈 cleanup

HMIR lowering은 제어 흐름이 현재 스코프를 벗어날 때 cleanup 명령을 명시적으로 삽입합니다. cleanup은 정상 블록 종료뿐 아니라 `반환`, `반복을 종료한다`, `다음 반복으로 넘어간다`, `종료` 같은 돌아오지 않는 호출에도 적용됩니다.

cleanup 순서는 다음과 같습니다.

1. 벗어나는 lexical scope의 `빌림끝`과 `주소고정끝`을 먼저 냅니다.
2. 벗어나는 owner 지역 값의 release 호출을 냅니다.
3. 벗어나는 `선점금지 작업` 수만큼 `커널선점허용` 호출을 냅니다.
4. 원래 제어 흐름 명령인 `반환`, `이동`, noreturn 호출 뒤 `도달불가`를 냅니다.

예를 들어 `선점금지 작업` 안에서 빌린 문자열을 가진 채 `반복을 종료한다`가 실행되면 HMIR은 반복 끝 라벨로 이동하기 전에 빌림을 닫고 owner를 release하고 선점금지를 풉니다.

```hmir
호출 @커널선점금지[]()
빌림끝 빌린문구
%1: 문자열 = 읽기 문구
호출 @문자열해제[문자열](%1)
호출 @커널선점허용[]()
이동 .반복끝_3
```

반복 제어 cleanup의 목표는 함수 바깥이 아니라 반복 라벨입니다. 따라서 반복 진입 전에 살아 있던 owner와 borrow는 유지하고, 반복 본문 또는 더 안쪽 블록에서 만든 값만 닫습니다. `반환`과 `종료`는 함수 실행을 끝내므로 함수 본문에서 열린 cleanup 대상을 모두 닫습니다.

호출 lowering도 owner 임시값을 별도 cleanup frame으로 관리합니다. 일반 매개변수에 전달한 이름 lvalue는 호출자가 계속 소유하지만, 함수 반환값·구조체값·배열값처럼 새로 생긴 owner rvalue는 호출 직후 역순으로 release합니다. `소비하는` 매개변수는 이 frame에 넣지 않습니다. 소비 owner 매개변수를 함수 본문의 새 지역 owner에 직접 초기화하면 HMIR은 retain 대신 `소유권이동 매개변수 -> 지역` marker를 내고 원래 이름을 제거합니다. 매개변수를 그대로 반환할 때도 반환 임시값으로 같은 marker를 냅니다. 인자를 왼쪽부터 평가하는 도중 `시도`가 실패하면 이미 만들어진 바깥 호출의 owner 임시값을 실패 라벨로 이동하기 전에 release하고, 성공 경로의 호출 후 cleanup과는 제어 흐름상 겹치지 않습니다.

owner 참조 수를 함수 본문에서 직접 감소시키는 terminal destructor의 매개변수는 표면 선언부터 `소비하는`이어야 합니다. 그래야 HMIR 호출 frame이 fresh 인자를 호출 후 다시 release하지 않습니다. `문자열해제`와 타입별 `동적배열해제`는 이 규칙을 따르며, 일반 borrowed 매개변수로 destructor를 구현하는 것은 이중 해제를 만드는 잘못된 ABI 계약입니다.

구조체 초기값의 소유 필드도 완성 전에는 같은 임시 cleanup frame에 들어갑니다. 뒤 필드를 계산하는 `시도`나 `기다림`이 실패하면 앞 필드를 역순으로 해제하고, 성공하면 완성된 구조체로 넘기며 임시 목록에서만 제거합니다. 소비 매개에서 이동한 필드와 새로 만든 필드 모두 이 규칙을 따릅니다. 이미 소유한 임시 구조체의 필드 투영은 다시 retain하지 않습니다.

소유권 검증 책임은 두 층으로 나뉩니다. 프론트엔드 타입 검사는 표면 문법 정책과 사용자 친화적인 조기 오류를 담당합니다. 예를 들어 `빌려온다`, `가져온다`, 수동 해제, 소유권 넘김, 주소 고정이 위험 작업 안에 있는지 확인하고, 소스 코드의 타입과 스코프 오류를 좋은 위치에서 보고합니다. HMIR ownership verifier는 최종 방어선입니다. `.hmje`에서 생성된 HMIR뿐 아니라 `.hmir` 직접 입력도 LLVM으로 내려가기 전에 같은 소유권 marker 검증을 반드시 통과해야 합니다.

빌림은 시작/끝 marker로 남기며, 시작 marker는 가능한 경우 원본 소유자 출처를 함께 기록합니다. HMIR lowering은 현재 lexical block 기준으로 빌림을 닫습니다. 즉 `빌림끝`은 참조의 마지막 사용 지점이 아니라 해당 블록이 끝나는 지점에 나옵니다. last-use 기반 NLL은 아직 적용하지 않습니다.

```hmir
위험구역
  변수 빌린값: 문자열 = %1
  빌림시작 빌린값 <- 원본
  ...
  빌림끝 빌린값
위험구역끝
```

출처를 알 수 없는 원시 주소에서 빌린 경우에는 `빌림시작 빌린값 <- ?`로 출력됩니다.

안전한 `참조한다`도 같은 marker로 표현됩니다.

```hmir
상수 빌린이름: 문자열 = %1
빌림시작 빌린이름 <- 작업값
호출 @출력[문자열](빌린이름)
빌림끝 빌린이름
쓰기 작업값.이름 = %2
```

주소 고정은 위험 작업 안에 marker로 남깁니다. 현재 lowering은 런타임 pin table을 호출하지 않고 LLVM 주석 marker로 보존합니다.

```hmir
위험구역
  주소고정 버퍼
  ...
  주소고정끝 버퍼
위험구역끝
```

소유권 넘김은 owner 이름을 현재 스코프에서 제거하고 감사용 marker를 남깁니다. 대상은 아직 런타임 호출로 해석하지 않으며, LLVM lowering에서는 주석 marker로 보존합니다.

```hmir
위험구역
  소유권넘김 값 -> 커널
위험구역끝
```

HMIR은 ownership verifier를 통과해야 LLVM으로 내려갈 수 있습니다. verifier는 `빌림시작/빌림끝`, `소유권이동`, `소유권해제`, `소유권잊음`, `소유권넘김`, `주소고정/주소고정끝` marker를 기준으로 최소 소유권 규칙을 다시 검사합니다.

- 소유권이 제거된 이름은 다시 읽거나 그 필드·원소를 쓸 수 없습니다. 지역 전체에 새 값을 쓰는 재초기화는 허용합니다.
- 고정된 owner는 쓰기, 해제, 이동, 잊기, 소유권 넘기기를 할 수 없습니다.
- `빌림시작 값 <- 원본`으로 열린 빌림이 살아 있는 동안 원본 owner는 쓰기, 해제, 이동, 잊기, 소유권 넘기기를 할 수 없습니다.
- 빌린 값은 반환할 수 없습니다.
- 빌린 owner 값은 동적 배열 같은 소유 컨테이너에 저장할 수 없습니다.
- 빌림과 주소 고정은 반드시 끝 marker로 닫혀야 합니다.
- HMIR 파일을 직접 입력해도 같은 검증을 거칩니다.

verifier는 라벨, `분기`, `스위치`, `이동`, `반환`, `도달불가`, 비동기 실패·취소 반환을 기준으로 제어 흐름 그래프를 따라갑니다. 함수마다 독립된 상태로 시작하고 도달 가능한 블록의 소비·빌림·주소 고정 상태를 합류하여 고정점까지 검사합니다. 서로 배타적인 경로의 cleanup은 허용하지만 한 경로에서라도 소비한 값을 합류 뒤에 읽으면 거부합니다. 루프를 다시 돌 때도 같은 규칙을 적용합니다. 모든 종료 경로에서는 열린 빌림과 주소 고정이 남아 있지 않아야 합니다.

## 메모리와 포트

타입 단위 포인터 읽기:

```hmir
%3: 자연수8 = 포인터읽기 %주소, %순번, 자연수8
```

타입 단위 포인터 쓰기:

```hmir
포인터쓰기 포인터 %주소, %순번, 자연수8, %값
```

바이트 오프셋 읽기:

```hmir
%3: 주소 = 오프셋읽기 %주소, 주소
```

바이트 오프셋 쓰기:

```hmir
포인터쓰기 오프셋 %주소, 자연수32, %값
```

문자열 바이트 읽기:

```hmir
%3: 자연수8 = 문자열바이트읽기 %문자열, %순번
```

포트 입출력:

```hmir
%1: 자연수8 = 포트읽기 %포트, 자연수8
포트쓰기 %포트, %값, 자연수16
```

대기:

```hmir
대기밀리초 %1
```

## 비동기 코루틴

비동기 함수와 구조화된 기다림은 다음 명령으로 보존합니다.

```hmir
비동기함수 문서준비(경로: 문자열) -> 문서
  %1: 주소 = 비동기시작 @PDF열기[문자열](%경로)
  비동기기다림 %1
  %2: 문서 = 비동기결과 %1
  반환 %2: 문서
함수끝
```

고정 sibling 집합은 모든 `비동기시작` 뒤에 하나의 `동시기다림`을 둡니다.

```hmir
%1: 주소 = 비동기시작 @PDF열기[문자열](%경로)
%2: 주소 = 비동기시작 @모델불러오기[문자열](%모델경로)
동시기다림 %1, %2
%3: 문서 = 비동기결과 %1
%4: 모델 = 비동기결과 %2
```

- `비동기시작`은 초기 중단점에 멈춘 coroutine handle을 만듭니다.
- `비동기기다림`은 자식 하나를, `동시기다림`은 모든 자식을 라운드로빈으로
  재개합니다. 비동기 함수 안에서는 부모도 중단하고, compiler-owned root에서는
  process entry가 완료까지 pump합니다.
- `비동기결과`는 final suspend를 확인하고 promise 값을 옮긴 뒤 frame을 destroy합니다.
- 반환값 없는 자식은 합류 뒤 `비동기정리`로 frame을 destroy합니다.
- 비구조적 작업은 캡처 환경을 한 번 참조한 뒤 `비동기인계 handle, 함수값`으로
  실행기 소유에 넘깁니다. 실행기는 root/UI 안전 지점에서 이를 재개하고 완료 시
  frame과 함수값 참조를 함께 정리합니다. 이 handle은 합류 집합에 남지 않습니다.
- LLVM lowering은 `llvm.coro.id/begin/suspend/resume/done/promise/destroy/end`를
  사용하고 함수에 `presplitcoroutine`을 붙입니다. suspension마다 새로 할당하지 않고
  호출당 frame 하나만 할당합니다.

플랫폼 완료 사건을 기다리는 compiler-generated 외부 비동기 wrapper는 다음 내부
명령을 사용합니다.

```hmir
%1: 자연수 = 비동기사건만들기
호출 @외부:native_start[자연수, 자연수](%값, %1)
비동기사건기다림 %1
%2: 자연수 = 비동기사건결과 %1
```

- `비동기사건만들기`는 host runtime의 불투명 completion token을 만듭니다.
- `비동기사건기다림`은 현재 coroutine을 blocked로 표시하고 중단합니다. callback이
  큐에 완료를 게시하면 root executor가 안전 지점에서 다시 drive합니다.
- `비동기사건결과`와 `비동기사건완료`는 완료를 정확히 한 번 소비합니다. HMIR
  verifier는 생성→대기→소비 선형성을 검사합니다.
- nested join은 미완료 child 각각의 blocked 상태를 합성합니다. 전부 blocked일 때만
  root가 `hmje_async_wait_for_wake`에서 잠들므로 CPU-only cooperative child는 계속
  진행하면서 외부 사건만 기다리는 트리는 busy-poll하지 않습니다.

## ABI 메모

HMIR v0.1은 ABI 결정을 명령어에 직접 모두 펼치지 않습니다. ABI 규칙은 백엔드 lowering 단계에서 적용합니다.

- 스칼라와 문자열은 값 전달입니다.
- 문자열은 `{주소, 길이}` 값입니다.
- 구조체와 고정 배열은 16바이트 이하이면 값 전달/값 반환입니다.
- 16바이트 초과 구조체와 고정 배열은 주소 전달 또는 숨은 반환 포인터를 사용합니다.

이 규칙은 `docs/language.md`의 ABI v0.1과 일치해야 합니다.

## 구현과 제한

컴파일 경로는 HMJE 구문 분석·타입 검사·HMIR 생성·소유권 검증·LLVM 코드 생성 순서로 구성됩니다. 공개 소스에서 각 단계의 구현을 확인할 수 있습니다.

- [HMIR 생성](../compiler/Sources/HMIR생성/): 타입 검사 결과를 중간 표현으로 변환합니다.
- [HMIR 처리](../compiler/Sources/HMIR/): 중간 표현의 구조와 검증을 정의합니다.
- [LLVM 코드 생성](../compiler/Sources/LLVM/): ABI·명령·함수 본문을 LLVM IR로 낮춥니다.
- [변환기](../compiler/Sources/변환기.hmje): 파일 처리·캐시·소유권 검증·출력을 조정합니다.

`.hmir` 파일은 프런트엔드를 거치지 않고 직접 입력할 수 있습니다. `hmjec --target posix-host-exe X.hmir` 또는 `hmjec --target posix-host-llvm-ir X.hmir`를 사용합니다. 소유권 검증은 기본으로 수행하며 `--소유권검증`은 호환 옵션입니다.

소유권 검증은 명시적인 소비·빌림·주소 고정 명령의 제어 흐름을 검사합니다. 이는 프로그램 전체의 정확성이나 모든 SSA 지배 관계의 증명을 의미하지 않습니다. 낮추기와 최적화의 구체적인 지원 범위는 위 구현을 따릅니다. 언어 수준의 소유권·ABI·비동기 계약은 [언어 명세](language.md)에 정의되어 있습니다.
